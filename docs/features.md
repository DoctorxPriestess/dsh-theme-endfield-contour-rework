# 设置项与功能

设置项的行为、默认值、字段名与边界情况。设计取值见 [design-language.md](design-language.md)，实现细节见 [engineering-notes.md](engineering-notes.md)。

设置入口：**设置 › 终末地主题设置**。全部文案跟随 DSH 的语言设置（中/英）即时切换，无需刷新。

## 持久化方式（不再用 localStorage）

历史内存风格：这些开关最初存浏览器 `localStorage`。由于浏览器存储按「协议 + 主机 + 端口」的 origin 隔离，而 DSH Desktop 每次启动都在 127.0.0.1 绑定一个**随机临时端口**，端口一变 origin 就变，上次保存的设置永远读不到，表现为「重启后恢复默认」。已改用 DSH 官方的用户设置命名空间：

- **浏览器端（client.js）** 通过 `ctx.settingsScope` 服务绑定命名空间 `dsh-theme-endfield-contour-rework`，读取/写入并订阅变化；
- **Host 端（index.js）** 通过 `ctx.settings.register('dsh-theme-endfield-contour-rework', schema)` 声明参数 schema，由 `@deepseek-ai/dsh-settings-file` 落到 `<dshHome>/settings.yaml`（DSH Desktop 的 profile 下同样适用）。

落盘位置由 DSH 决定（`$DSH_HOME` 或 `~/.dsh/...`），与浏览器 origin/端口无关，因此在 **dsh web（浏览器、固定/默认端口）** 和 **DSH Desktop（随机临时端口）** 两种运行方式下设置都能正确持久化——它们跑的都是 127.0.0.1 loopback 页面，DSH 会把连接解析为 `host` 持久化模式。

下表「字段」（缩写）就是命名空间里的存储字段，语义等价于旧 localStorage 键名的尾部。

## 01 主题

### 终末地主题（总开关）

关闭后移除令牌层与样式表，界面回到应用原生外观，无需刷新。它同时是**所有其他功能的总闸**：关闭会一并拆掉水印、等高线、大字与订阅。

**关闭后设置页仍保持可读。** 这一点需要专门处理：开关按钮的强调色底来自主题自己的样式表，样式表随主题关闭而移除，所以关闭时按钮回退到应用原生令牌（选中态实心底、常态透明描边），而不是留下「黑字落在深色面板上」的不可读状态。

### 主题配色

在**谷地黄**（默认，`#fff500`）与**武陵青**（`#14d0d0`）之间切换。设置行带一个色块预览，而不只是写颜色名。

切换只是 `<body>` 上加减一个 class，不重新注册令牌层、无 JS 重绘。唯一的例外是等高线画布（canvas 描边不能是 CSS 变量），由 `MutationObserver` 监听 class 变化触发重绘——顺带让「别的标签页改了配色」也能跟着变。

### 主题圆角

直角（默认）/ 圆角。同样是一个 class：`body.theme-endfield-round` 让整组 `border-radius: 0` 规则失效，恢复应用原生圆角。

## 02 背景

### 等高线背景（默认关闭）

参考等高线地形图：整屏铺满强调色细线。图案是一张**可平铺的地形等高线纹理**：连续山脊、谷地、缓坡与开放曲线，闭合环线相互嵌套成大小不一的「岛屿」。

线不是贴图也不是手绘路径，而是**标量场的真等值线**：

- **地形** = 可平铺的 Perlin 梯度噪声 + 多倍频（fBm，persistence 与倍频数由「地形粗糙度」决定），在 10px 网格上采样，再按档位叠一层**解析式地貌层**（高原 / 悬崖 / 山脊线 / 深谷 / 水面 / 各类地貌斑块，见下）；
- **线** = marching squares 在该高度场上取等值线（数量由「等高线密度」决定：8 / 14 / 22 / 34 条）；
- **连线** = 交点按边 ID 缝合成连续折线（开放与闭合都保留），再经 Chaikin + 受限 Catmull-Rom 平滑后**一次性**画进缓存画布；
- **动画** = 只把这张缓存纹理按方向整体平移（接缝处环绕拼接），地形本身永不变形、永不重新提取。

噪声周期与纹理尺寸一致，所以纹理左右/上下边界天然连续：滚动时看不到接缝。纹理尺寸按视口动态计算（约 3 倍视口，量化到 128px，并受总面积 8.3e6 CSS px² 与单边 4096 设备像素上限约束），默认 48 px/s 下横向周期约 70 秒，正常观看不易察觉重复。每次开启背景会重新生成新的随机地形；同一次运行中的 resize 会用同一个 seed 重算，因此不会随机换地图。

算法细节与实测数据见 [engineering-notes.md § 等高线](engineering-notes.md#等高线背景).

**图层挂在应用外框内部**，`inset:0; z-index:0`，落在「外框底色之上、所有定位子元素之下」。正文永远在图层之上，前景对比度不受影响。挂载期间会把外框、对话列、详情列与侧栏的不透明底色置为透明（`:has()` 守卫使功能关闭时全部规则失效）。

**关闭时零逐帧开销**——不是在 rAF 里空转再提前返回，而是整个循环停掉；关闭后图案仍然显示（它是一张静态图）。

### 等高线滚动（默认开启，需先开启等高线背景）

缓存好的纹理沿所选方向匀速平移。**速度以像素/秒计**（`12 / 24 / 48 / 96 / 192`），位移按 `px/s × 实际帧间隔秒数` 计算，所以在 60 / 120 / 144 / 240 Hz 下视觉速度一致。跟随设置：「滚动方向」8 个方向（`↑ ↗ → ↘ ↓ ↙ ← ↖`，写入 `contour-dir`）、「滚动速度」五档（写入 `contour-speed`）、「等高线密度」四档（写入 `contour-density`，只重新提取等值线，不重新生成地形）、「地形粗糙度」十二档滑块（写入 `contour-roughness`，**重新生成地形**）。非法值自动回退到默认值。

改方向或速度只更新两个缓存数值，改密度只对**同一个地形**重新提取一次，两者都不会重新生成地形。

### 地形粗糙度（滑块，12 档；需先开启等高线背景）

这是唯一改变**地形本身**形状的设置，而且它改的不只是「多细」，还有**地形类型**与**地貌特征**。档位把滑块从平原一路推到高山，每一档选一种基本地形（平原 / 丘陵 / 低山 / 中山 / 高山），并在其上叠加对应的特征地形（高原、悬崖、山脊线、山谷线、冲沟、尖锐山峰、深谷、湖海与各种地貌斑块）。

基本地形由柏林噪声 fBm 的三个参数决定：

| 参数 | 平原端（第 1 档）| 山地端（第 12 档）| 作用 |
| --- | --- | --- | --- |
| 最大噪声单元 | 960 px | 600 px | 山体尺度（低档逐渐变小，山地段转而变大：**山更少更大**，细节交给地貌层）|
| persistence | 0.24 | 0.56 | 细节层振幅占比 |
| 倍频上限 | 2 | 5 | 细节层数（受纹理分辨率自动截断）|

**出厂档位是第 8 档（`contourRoughness = '7'`）**，它的三参数**逐字等于**主题一直以来的常量 `280 / 0.5 / 5`（由 `test/contour-roughness.test.js` 断言）。注意：从 1.3.0 起**默认档的地形观感会与 1.1/1.2 不同**——因为地貌层（下面的「特征地形」）在默认档起就已生效，这是需求明确要求的行为。

拖动滑块会**用同一个 seed 重新生成地形**，所以「重新调粗糙度」不会把地图换掉，只是把同一片地形重新塑形（与 resize 的确定性重算同一套逻辑）。拖动过程按档位触发，合并成最后一次变更后重建一次（1920×1080 下最坏 ~117 ms），不会每档都卡一帧。

### 特征地形（每一种占比都 < 75%）

地貌层是**解析式**的：没有任何流体侵蚀或堆积模拟，所有特征都由「高度重映射」或「局部解析斑块」生成。之所以这样划线：真正的过程模拟需要对整块纹理做多趟非局部迭代，单次重建会从 ~100 ms 变成秒级，还会破坏滚动所依赖的**精确可平铺**保证，而在一张 1px 描边的背景图上根本看不出区别。等高线图能表现的「地貌」本来就是**等值线的形状**，而下面每一种形状都能用解析方式做出来：

| 特征 | 实现 |
| --- | --- |
| 陡坡 / 缓坡、凸坡 / 凹坡、均坡 | 高度重映射 `u^k`，指数随低频掩膜变化：`k<1` 线束压在下缘（凸坡），`k>1` 压在上缘（凹坡）|
| 阶梯坡 / 高原 | 软阶梯（宽踏步）：平台内部等值线穿不过去 → 成片空白 |
| 悬崖（陡崖）| 同一种阶梯的**另一种形状**（多级 + 窄坡面），且**只作用在带状掩膜内** → 线束沿坡面排开 |
| 山脊线（分水岭）| ridged noise `1-|n|` 叠加：零交叉线即山脊 |
| 山谷线 / 冲沟 | 自身倍频的零交叉处下切窄槽 |
| 尖锐山峰 / 深谷 | 单调多项式 `u + 2r·u(1-u)(2u-1)`：两端（峰与谷）梯度放大到 `1+r`，中段放缓 |
| 海 / 湖 / 河漫滩 / 潟湖 | **精确平面**：低于水位的高度一律钳到水位（水面在等高线图上就是平的，平的地方不画线）|
| 冲积扇 / 洪积扇 / 泥石流扇 / 三角洲 | 扇形体（顶点在中心，向外凹形展开）|
| 火山锥 / 火口湖 | 锥体 + 顶部火口 |
| 冰斗 / 天坑 / 矿坑 / 牛轭湖 / 潟湖 | 碗形或近圆柱形洼地（洼底低于水位时自动成为湖）|
| 峰林 / 峰丛 / 角峰 | 斑块内部多个尖锐塔状峰 |
| 刃脊 / 沙嘴 / 堤坝 | 细长脊线 |
| 峡湾 / 阶地河道 / 河漫滩 | 细长槽谷，横剖面自带台阶（阶地的样子）|
| 沙丘 / 雅丹 | 定向波纹，边缘阻尼到 0 |
| 倒石堆 | 低矮锥体 |
| 极端形状 | planar 一律为平滑函数，**没有硬量化/折角**（见下）|

**高原与悬崖随档位的变化**（这是需求里点名要的）：

- **高原**：第 6 档出现（强度 0.75），第 7/8/9 档逐档降到 0.60 / 0.45 / 0.20，**第 10 档起为 0** —— 平坦地形随粗糙度**递减**直至消失，不再把山地一刀砍平；
- **悬崖**：第 8 档起步（0.10），第 9–12 档 0.22 / 0.40 / 0.62 / **0.90**，且**带状宽度也逐档变宽**：第 10 档「有一点悬崖」，第 12 档悬崖占比**最多**（实测 27.0%）。

**每一种「特征地形」的合计占比都 < 75%**（实测最粗档 44.0%，各档见下表），另外至少 25% 的画面必须留给定型地形——这条上限在测试里逐档断言。

几何验证（`test/contour-roughness.test.js`，固定 seed、3840×2160 纹理、14 条等值线）：

| 档 | 地形类型 | 最大单元 | 闭合环 | 总笔画 | 特征占比 | 高原占比 | 悬崖占比 | 水面占比 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | 平原 | 960 px | 18 | 139k px | 17.4% | — | — | 15.9% |
| 5 | 低山 | 480 px | 207 | 303k px | 4.2% | — | — | 0.6% |
| 6 | 低山 | 427 px | 329 | 343k px | 28.8% | 25.8% | — | 0.1% |
| 8 | 中山（默认）| 280 px | 669 | 486k px | 40.8% | 21.5% | 11.6% | — |
| 9 | 中山 | 360 px | 533 | 467k px | 41.0% | 15.1% | 15.7% | — |
| 10 | 高山 | 440 px | 562 | 473k px | 31.5% | — | 20.0% | — |
| 11 | 高山 | 520 px | 490 | 477k px | 37.5% | — | 20.6% | 1.3% |
| 12 | 高山 | 600 px | 608 | 503k px | 44.0% | — | 27.0% | 1.1% |

**滑到高档不会「反而变平」**：第 9–12 档是高山段，笔画必须逐档增加（实测 467k → 473k → 477k → 503k）。这条当初就是被漏掉的——第 10 档曾带着一个**盆地偏向**（宏观高程 −0.16，而 11/12 档是 +0.20 / +0.26），一个「高山」档却向低地塌陷，实测笔画 429k 比两侧的 467k / 477k 低 9%，滑块往上滑画面反而更平静。测试现在按实测场断言这一点：高山段任何一档的笔画不得低于左右邻档均值的 95%（第 8→9 档是「中山→高山」的换挡处，刻意豁免，设计上在这里用山体数量换地貌戏剧性）。

**「特征地形」的判定口径**（写进测试，不靠肉眼）：每个格子记录「被地貌层移动了多少（占高度范围的比）」与「是谁移动的」；移动量 ≥ 2%（约等于一个等高距）即计入特征占比，并按最强的那一项归类。因此上表的「高原/悬崖/水面占比」是**生成器自己的账本**，不是事后猜测。

**可平铺性与确定性**：所有特征都作用在**环面坐标**上（斑块用最短有符号偏移、掩膜用可平铺噪声），因此跨越纹理边界的地貌在两侧绘制完全一致——测试逐档断言「首列 == 末列、首行 == 末行」（实测误差**恰好为 0**）。阶梯/重映射都是逐点映射，所以「同 seed + 同尺寸 → 逐位相同」。

**为什么没有折角**：阶梯用 smoothstep 软边而不是 `floor()`；尖锐山峰用**导数有限**的多项式而不是 `u^p (p<1)`（后者在端点斜率为无穷，最内圈等值线会细过 10px 采样网格而糊成噪点）。`test/contour-cusps.test.js` 现在把**每一个带地貌的档位**单独扫一遍（两个尺寸 × 两个密度 × 全部 12 档），实测最大转角仍是 **1.1°**，与改动前完全一致。

**可读性上限**：每档按「每条等值线的折线数」度量（3840×2160、14 条等值线），最挤的是第 8 档 61 条/级；超过约 90 条/级画面就从「地形」退化成均匀噪点，测试按此设上限。

### 背景水印（默认开启）

`ENDFIELD` 大字水印，默认只在**新建会话页**（hero）显示，居中跟随标题。

- `pointer-events: none`，不拦截点击与文本选择；
- 强度按配色分别声明为 CSS 变量 `--edge-wm-alpha`（亮 `0.13` / 暗 `0.085`），配色切换时自动重解析；
- 深色模式取更低的 alpha：在近黑底上**叠加**亮度，比在纸底上**减去**亮度显得响得多。

**防浏览器误翻译**：字形由 CSS `content`（`::before`）绘制，元素本身没有任何 DOM 文本节点，逐文本节点遍历的翻译器看不到它；另加 `translate="no"`、`class="notranslate"`、`lang="en"`、`aria-hidden="true"`。

### 水印保持显示（默认关闭，需先开启背景水印）

开启后，对话页等非新建会话页面也显示水印。

此时水印挂载在**会话列内部**，以 `z-index: -1` 位于正文**之下**（该列在水印挂载期间获得 `isolation: isolate` 与 `position: relative`，卸载后自动还原）。之所以不挂 `<body>`：一个 fixed 的 body 子节点会画在消息文字**之上**，把用户正在读的内容洗白。

## 03 动画

### 启动加载动画（默认关闭）

参考终末地官方主视觉：整屏黑底，左边缘 10px 强调色进度轨自上而下填充。**刻度 + 百分比 + 状态行跟随进度轨的填充端一起下移**，并做了下边界钳制，接近 100% 时不会滑出屏幕。

播放时序（开启后每次刷新页面播放一次）：

| 阶段 | 时长 | 表现 |
| --- | --- | --- |
| 进度 | 约 1750ms（`easeOutCubic`） | 强调色进度轨自上而下填充，读数随之下移 |
| 横向铺满 | 520ms | 到 100% 后进度轨从 10px 横向展开成整屏 |
| 整屏淡出 | 620ms | 连同整块遮罩淡至透明，节点随即从 DOM 移除 |

设置行提供「预览」按钮，可不刷新页面直接重播一次。

**海报式排版**：品牌块**内部左对齐**（各行共用同一条左侧节奏线）但整体**摆在画面右侧**——这个组合才是参考图的观感。`END` / `FIELD` 上下两行紧排堆叠，不含中文字标。字标尺寸 `clamp(26px, min(5.2vh, 4.8vw), 64px)`，取较小轴，因此无论窗口「矮」还是「窄」品牌块都不会挤进左侧进度轨。已在 520×900 到 2560×1440 共 13 种视口逐一验证无溢出。

工程要点：

- **进度由墙钟时间推导**（非逐帧累加），不会漂移；
- **双时钟驱动**：`requestAnimationFrame` 负责平滑更新，`setInterval` 兜底——rAF 在后台标签页与无头渲染器中会在首帧后停摆，仅靠它会让全屏遮罩永久留在屏幕上；
- **收尾动画也由 JS 驱动，不用 CSS transition**（原因见工程笔记）；
- **硬性保险丝**：一个独立 `setTimeout` 终点，即使所有时钟停摆也必定移除遮罩；
- `prefers-reduced-motion` 下直接跳过铺满与淡出，立即移除遮罩；
- `pointer-events: none`：动画进行中也不拦截点击；
- 全部字形由 CSS `content` 绘制 + `translate="no"`，防浏览器翻译改写品牌名。

`z-index: 2147483000` —— 加载屏是唯一有资格独占整屏的表面。

## 04 娱乐

### 雷霆大字（默认关闭）

任务开始 / 结束时，在屏幕正中用白色粗体大字打出「任务开始」/「任务完成」，**3 秒后自动隐藏**，**期间点击屏幕任意处可立即关闭**。设置行提供「预览」按钮。

**状态信号取自唯一权威位**：`@deepseek-ai/dsh-client-runtime` 的 `ConversationSnapshot.running`——应用自己的回合状态标签与停止按钮切换的就是这个字段。不去监听转圈图标或类名：那些类名带构建哈希、并非契约，而且「出现了一个 spinner」和「一个回合开始了」并不是同一件事。

**只认边沿，不认电平。** 一个回合进行中，快照存储会以每秒几十次的频率推送；只有 `false → true` / `true → false` 的跳变才播报。每个会话**第一个可读到的值记为基线并保持静默**，因此「切进一个已经在跑的会话」不会误报「任务开始」——但该会话结束时仍会正常播报「任务完成」。

**点击关闭的监听挂在 `document` 的捕获阶段**，遮罩本身保持 `pointer-events: none`：

- 一次按下**同时**完成两件事——关掉大字，并正常抵达用户真正瞄准的元素；
- 用 `pointerdown` 而非 `click`：一个事件覆盖鼠标 / 触摸 / 触控笔，且按下即消失；
- 用**捕获阶段**：菜单、下拉、拖拽手柄常在自己的处理器里调 `stopPropagation`，冒泡阶段听不到那些按下，大字就会关不掉；
- 提前关闭会同时取消 3 秒定时器并摘掉监听器。

如果改成给遮罩加 `pointer-events: auto` 再挂 `onclick`，它会变成**一块持续 3 秒的全屏点击黑洞**：用户为了关掉它而点下去的那次点击会被吃掉。

层级 `z-index: 2147482000`，比加载遮罩低一档。整块 `aria-hidden`——纯装饰不该被读屏软件念出来。

**关闭即零开销**：关掉时不订阅、不留定时器、不建节点。

### 大字入场动画（默认关闭，需先开启雷霆大字）

| 状态 | 表现 |
| --- | --- |
| **关闭（默认）** | 大字**直接出现**在屏幕正中，保持 3 秒后消失，无缩放、无淡入淡出 |
| 开启 | 大字由大缩小「砸」入（`scale(2.4) → 0.94 → 1`）并在末尾淡出 |

与「等高线背景 → 等高线滚动」是同一种结构：**图层是一个决定，让它动是另一个决定**。

三个刻意的约束：

- **子开关只改入场表现，不改时长。** 3 秒由 JS 定时器持有，不挂在动画结束事件上——否则开关动画会顺带改掉停留时间。
- **未开启动画时，主开关关闭时该行为 disabled。** 一个对当前状态无意义的控件应该看起来就是不可用的。
- **系统「减少动态效果」仍然压过这个开关。** 两个独立原因（开关关闭、系统偏好）汇合到同一条静态分支；此时设置行会说明是系统偏好在生效。
